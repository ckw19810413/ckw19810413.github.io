## 王立写字院の機転の利く弟子

帝国の首都の中心にある王立写字院は、かつてない危機に直面していました。

帝国の首席大学士「バルタザール」は、神聖な法典を起草できるだけの叡智を持つ、この世でただ一人の人物でした。彼は一度見たものを決して忘れない記憶力を持ち、頭の中には一千万冊の古典が収められています。しかし、彼には致命的な欠点がありました。字を書くのがあまりにも遅いのです。

大学士の厳格さは偏執の域に達していました。一語書くたびに、彼は頭の中の図書館で無数の重厚な典籍をめくり、熟考に熟考を重ねてから、ようやくゆっくりと筆を下ろします。その一語を書き終えると、今しがた書いた内容をもとに、また次の一語を推敲するのです。そのため、彼は一分間に一語しか書けませんでした。前線は新しい法令を切実に求めているのに、大学士は一語ずつしか絞り出せません。

このとき、写字院には「レオ」という若い弟子がいました。レオの学識は大学士には遠く及ばず、頭に入っている書物は大学士の百分の一にも満たないほどでしたが、彼にはひとつの長所がありました。反応がきわめて速く、しかも大学士の心の内をよく言い当てるのです。

数日間観察したのち、レオは大学士に大胆な提案をしました。

「師よ、一語ごとに一から苦心して考えるより、働き方を変えてみてはいかがでしょう」とレオは言います。「私を『下書き役』にしてください。あなたが次に書きそうな五語を、一気に続けて推測し、石板に素早く書き記します。そのあと、あなたはこの石板を見るだけでよいのです」

大学士は眉をひそめました。「ばかげておる！お前の学識は浅い。書いた語が間違っていれば、法典の荘厳さを台なしにしてしまうぞ！」

「師よ、それは誤解です」とレオは微笑んで説明します。「**『何もないところから一語を構想すること』**には、頭の中の典籍を運ぶ大変な労力がかかります。しかし、**『さっと目を通して、いくつかの語が意にかなっているかを判断すること』**は、あなたにとってきわめて楽で速いのです。私が書いた語が正しいと思えば、そのまま印を押してください。もし一語でも意図と異なる語を見つけたら、その語とそれ以降をすべて消し、正しい語をご自身で書き入れてください。そうすれば、私はあなたが直した語をもとに、また先を推測していきます」

大学士は半信半疑ながら承諾しました。

作業が始まりました。レオは石板に素早く書きます。「帝国は／北方に／課税／する／であろう」。

大学士がさっと目を走らせると、頭の中で瞬時に検証が完了しました。この五語は彼の思考と完璧に一致していたのです！彼はすぐに大印を押しました。かつては五分かけて絞り出していた一文が、今や数秒で仕上がったのです。

続いてレオは素早く書きます。「税率は／年に／五十／枚の／金貨／とする」。

大学士はひと目見て眉をひそめ、四番目の語を指して言いました。「違う。五十ではない、『百』だ」。

大学士はすぐさま筆を振るい、「五十／枚の／金貨」をすべて消して、自らの手で「百」と書き入れました。

そして、レオは「百」という語を見て、再び素早い推測と下書きを始めます。

レオは時に推測を外すこともありましたが、大半の定型的な言い回しは正確に言い当てました。もっとも驚くべきは、この法典が最終的に示した品質と語句が、大学士自身が一語ずつ苦心して仕上げた結果と「まったく寸分たがわず」、いかなる妥協もないのに、起草全体の速度は何倍にも向上していたことです。

## 種明かし：投機的デコーディング (Speculative Decoding)

この物語が語っているのは、現代の大規模言語モデル (LLM) の推論高速化の分野における、きわめて優雅かつ重要な大学院レベルのアルゴリズム、**投機的デコーディング (Speculative Decoding)** です。これは、現代の高性能推論エンジン（vLLM など）がハードウェア性能の壁を突破するために用いる中核技術のひとつでもあります。

従来の LLM のテキスト生成では、モデルは**自己回帰 (Autoregressive)** の方式で、トークンを一つずつ順に生成しなければなりません。数百億パラメータ（Qwen 35B 級など）にもなる大規模モデルでは、単一トークンを生成するたびに、数十 GB もの重みを GPU のメモリから演算コアへ運ぶ必要があります。そのため、大規模モデルの推論のボトルネックは**演算能力 (Compute)** ではなく、**メモリ帯域幅 (Memory Bandwidth)** にあるのです——これはまさに、物語の中で大学士が一語を書くために重厚な典籍を苦労して運ばねばならないのと同じです。

**投機的デコーディング**は、この膠着状態を巧みに打ち破ります。
* パラメータがきわめて小さく、速度のきわめて速い**「ドラフトモデル (Draft Model)」**（弟子レオ）を導入し、一度に複数の連続したトークンを素早く生成させます。
* 次に、生成されたこれらのトークンを、巨大で正確な**「ターゲットモデル (Target Model)」**（大学士）に渡し、一回の**並列検証 (Parallel Verification)** を行わせます。
* ターゲットモデルは与えられたトークンを「検証」する際、GPU の並列演算の強力な演算能力（Compute-bound）を十分に活かせるため、これらのトークンの確率分布が自らの出力と一致するかを一瞬で判断できます。
* 受理されれば、一回の順伝播 (Forward Pass) で複数のトークンを同時に生成したことになります。拒否されるトークンがあれば、その地点で修正し、以降の推測を破棄して、やり直します。

最も魅力的な数学的性質はこうです。特定の検証用棄却サンプリングアルゴリズムによって、投機的デコーディングは、最終出力の確率分布が、ターゲットモデルが単独でゆっくり生成した場合の確率分布と数学的に「100% 等価」であることを保証でき、生成品質をまったく損ないません。

## 物語のメタファー対応表

| 物語の要素 | LLM 推論の概念 | 説明 |
|---|---|---|
| **首席大学士「バルタザール」** | ターゲットモデル (Target Model) | パラメータが巨大で精度の高い大規模言語モデル。 |
| **機転の利く弟子「レオ」** | ドラフトモデル (Draft Model / Proposer) | パラメータがきわめて小さく演算のきわめて速い小規模言語モデル（あるいは近年の MTP / Medusa などのマルチヘッド予測アーキテクチャ）。 |
| **重厚な典籍を運んで字を書く** | メモリ帯域幅の制約 (Memory-bandwidth bound) | 従来の自己回帰生成において、モデルの重みを運ぶことで生じる遅延。 |
| **石板の文をさっと見渡す** | 並列検証 (Parallel Verification) | ターゲットモデルが GPU の演算能力の利点を活かし、一回の Forward Pass で複数トークンの確率を同時に評価する。 |
| **印を押して承認／消して書き直す** | 受理・棄却基準 (Acceptance/Rejection Criterion) | ドラフトモデルの予測がターゲットモデルの確率許容範囲内なら受理し、外れれば誤り地点までロールバック (Rollback) してターゲットモデルが正しいトークンを与える。 |
| **品質がまったく変わらない** | 無損失生成 (Lossless Generation) | 投機的デコーディングの最も重要な数学的保証：ターゲットモデル本来の出力確率分布を変えない。 |
