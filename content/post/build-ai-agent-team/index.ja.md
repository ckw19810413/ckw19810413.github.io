## 20 分で初めての AI エージェントチームを構築する

2026 年、AI シーンを追っていたなら、この約束を必ず耳にしたことがあるでしょう——マルチエージェント AI システムは専門家のチームのようで、各自が最も得意な仕事を処理する。しかしほとんどの教學は理論の段階で止まっています——マルチエージェント協調が何かを説明するだけで、実際にどのように構築するかは教えてくれないのです。

この教學はそれを変えます。

この教學を完了した後、実際に稼働するマルチエージェント AI システムを手に入れることになります——登録済みエージェント、タスクキュー、そしてリアルなダッシュボードで——コードレビュー、コンテンツ制作、市場調査など、あらゆる作業を自動化するために使えます。

**今日学ぶこと：**

- 機械上で Cowork MCP Server を実行する
- 285 以上のデフォルト専門エージェントを揃える
- 構造化されたレポートを出力するマルチエージェントタスクをディスペッチする
- LLM バックエンドに接続して実作業を実行する

では始めましょう。

## 前提要件

始める前に、以下の準備が整っていることを確認してください：

|| 項目 | バージョン要件 | 確認コマンド |
||------|-----------|---------|
|| **Node.js** | ≥ 20（v22 を推奨） | `node --version` |
|| **npm** | ≥ 10 | `npm --version` |
|| **Git** | 任意のバージョン | `git --version` |
|| **LLM バックエンド** | 少なくとも一つ（Claude、GPT、Gemini またはローカル） | — |

これだけです。クラウドアカウントは不要、Docker は不要、複雑なインフラも不要。すべてはあなたのマシン上で動作します。

AI エージェントが初めての方は、[マルチエージェント AI 協調プラットフォーム完全ガイド](/multi-agent-coworking-platform/)を読んで基礎概念を理解することを推奨します。この教學はそれをベースに実装を行います。

## ステップ 1：Cowork のインストールと起動

Cowork MCP フレームワークはオープンソースで、二つのコマンドでインストールできます。

```bash
# リポジトリと全エージェント定義をコピー
git clone --recurse-submodules https://github.com/slashman413/cowork
cd cowork/server

# 依存関係をインストール
npm install
```

`--recurse-submodules` オプションが極めて重要です——`agency-agents` サブモジュールを取り込みます。ここには 285 以上の事前書かれたエージェント定義が含まれています。各エージェントは YAML フロントmatter を持つ `.md` ファイルで、役割、スキル、実行パラメータを記述しています。

### サーバーの起動

```bash
npm run dev
```

以下のような出力が表示されるはずです：

```
🤝 Cowork MCP Server running at http://0.0.0.0:6868
   MCP endpoint: http://0.0.0.0:6868/mcp
   Web Dashboard: http://0.0.0.0:6868/
   REST API: http://0.0.0.0:6868/api/
   Roster loaded: 285 agents across 19 divisions
```

**ブラウザで `http://localhost:6868/` を開いてください。** Cowork ダッシュボードが表示されます——エージェント roster、タスクインボックス、システムステータスが一目で分かります。

## ステップ 2：エージェント roster を理解する

Cowork には **285 以上の専門エージェント**が**19 の部門**に組織化されています。各部門は一つの専門領域に対応しています：

|| 部門 | エージェント数 | 例示エージェント |
||------|-----------|-----------|
|| エンジニアリング | 45+ | コードレビュアー、システムアーキテクト、DevOps エンジニア |
|| マーケティング | 30+ | SEO スペシャリスト、コンテンツストラテジスト、ソーシャルメディアマネージャー |
|| テスト | 25+ | QA エンジニア、ペネトレーションテスター、パフォーマンス監査 |
|| データサイエンス | 20+ | データアナリスト、ML エンジニア、ビジュアライゼーション専門家 |
|| デザイン | 15+ | UI デザイナー、UX リサーチャー、ブランドデザイナー |
|| 法務 | 12+ | 契約審査員、コンプライアンススペシャリスト |
|| 財務 | 18+ | 財務アナリスト、リスク評価者、税務スペシャリスト |
|| プロダクト | 10+ | プロダクトマネージャー、グロースハッカー、プロダクトマーケティング |
|| *その他 14 部門...* | | |

各エージェントは明確に定義された役割を持っています。ダッシュボード上で、または `cowork/agency-agents/agents/` パスを閲覧することで、full roster を確認できます。

## ステップ 3：LLM バックエンドを接続する

Cowork はタスクコーディネーター——作業をルーティングする役割ですが、それ自体は LLM リクエストを実行しません。少なくとも一つの「脳」（LLM 能力を持つプラットフォーム）に接続してエージェントを実行する必要があります。

### オプション A：Hermes Agent（初心者推奨）

[Hermes Agent](https://hermes-agent.nousresearch.com) を既にインストールしている場合、ネイティブに統合できます：

```bash
hermes register-cowork
```

これにより、Hermes が Cowork の作業ノードとして登録され、39 以上のスキルと内蔵ツールセットが開放されます。

### オプション B：Claude Code

Claude Code の MCP 設定ファイル（`~/.claude.json` またはプロジェクトレベルの `claude.json`）に以下の設定を追加します：

```json
{
  "mcpServers": {
    "cowork": {
      "url": "http://localhost:6868/mcp",
      "transport": "streamable-http"
    }
  }
}
```

### オプション C：任意の MCP 互換クライアント

Model Context Protocol (MCP) をサポートするすべてのクライアント——Cursor、VS Code 拡張機能、Gemini CLI、カスタムスクリプトを含む——は、Cowork の `/mcp` エンドポイントに接続できます。

接続が完了すると、エージェントが利用可能な作業ノードとして表示されます。Cowork のコーディネーターが以降の全作業を処理します。

## ステップ 4：初めてのマルチエージェントタスクをディスペッチする

ここから見どころ——エージェントチームを通じて実際に作業を実行します。

### タスク：マルチエージェントコード監査

GitHub リポジトリに対し、三人のエージェントで並列監査を実施しましょう。Cowork ダッシュボードまたは API 経由で：

```json
{
  "title": "包括的コード監査 - agents-coworking",
  "description": "agents-coworking GitHub リポジトリの包括的監査：コード品質（テックリード）、UX/SEO（グロースハッカー）、実行可能ロードマップ（プロダクトマネージャー）を評価。",
  "skill": "engineering",
  "tags": ["code-review", "security", "performance"],
  "to_agent": "tech-lead",
  "priority": "high"
}
```

Cowork のコーディネーターは三つのフェーズで処理します：

**フェーズ 1 — 分類：** クラッファ脳がタスク説明を読み、所属部門を判断します。「コード監査」＋ engineering、code-review タグ → エンジニアリング部門。

**フェーズ 2 — エージェント選択：** エンジニアリング部門内で、コーディネーターはスキルマッチング、専門の深さ、現在の負荷に基づいて利用可能なエージェントを評価し、最も適したエージェントを選択します。

**フェーズ 3 — 実行：** 選択されたエージェントがあなたの LLM バックエンド上で実行し、完全なタスク説明をコンテキストとして受け取り、構造化された出力を生成——通常は `cowork/reports/` 内の markdown 報告書として保存されます。

ダッシュボードでリアルタイムの進捗を監視できます：

```
━━ タスク：包括的コード監査 ━━
  エージェント：テックリード（Hermes Agent 経由）
  ステータス：実行中…（3 分経過）
  進捗：コード構造分析 → 依存関係監査実行
```

### チェーンタスク：複雑なワークフロー

本番環境では、タスクをチェーンして、あるエージェントの出力を次のエージェントの入力にできます：

```
リサーチエージェント → コンテンツライター → SEO 最適化 → ソーシャル投稿
    │              │            │            │
    ├ 主題分析      ├ ブログ草稿    ├ メタタグ     ├ プラットフォーム投稿
    ├ 競合情報      ├ 2000+ 文字    ├ Schema     ├ スケジュール
    └ キーワード研究 └ トーン一致    ├ インリンクリンク  └ 分析設定
```

各エージェントがその出力を次のエージェントにコンテキストとして渡します。結果として、主題選択からコンテンツ公開まで、一度のコーディネーションで完了します。

AI ドライブンなコンテンツ戦略とプロンプトについては、私の [AI プロンプトスキルガイド](/ai-prompts-guide/)を参照して、すぐに使えるテンプレートをご覧ください。

## 実用パターン 1：自動化コードレビューパイプライン

**目標**：GitHub にコードをプッシュするたび、Cowork が自動的にコードをレビューする。

**設定**：
1. Cowork タスクテンプレートを作成
2. GitHub Action でプッシュのたびに Cowork の API に POST
3. Cowork がテックリードとセキュリティエージェントにタスクをディスペッチ
4. 結果は PR コメントとしてフィードバック

```yaml
# .github/workflows/cowork-review.yml
on: [pull_request]
jobs:
  ai-review:
    runs-on: ubuntu-latest
    steps:
      - name: Dispatch Cowork Review
        run: |
          curl -X POST http://your-server:6868/api/tasks \
            -H "Content-Type: application/json" \
            -d '{
              "title": "PR Review: ${{ github.event.pull_request.title }}",
              "description": "Review PR for security, performance, and code quality",
              "skill": "engineering",
              "tags": ["code-review", "ci-cd"]
            }'
```

## 実用パターン 3：プロダクトローンチ調整

デジタルプロダクトのリリースには、リサーチ、コンテンツ、技術設定、分析の調整が必要です。マルチエージェントチームがエンドツーエンドでこれをすべて処理します：

1. **市場リサーチエージェント** — 競合他社を分析し、価格ギャップを特定し、競合情報名を生成
2. **コンテンツストラテジスト** — ランディングページコピーを執筆し、プロモーション素材を作成し、メールシークエンスを設計
3. **テクニカルスペシャリスト** — デプロイ、支払い統合、アナリティクス設定を処理
4. **プロダクトマネージャーエージェント** — 全出力をローンチスケジュールに統合

これが私が [Slashman Tools](/zh-tw/) で新しいプロダクトをリリースする際に使用しているパターンです。マルチエージェントのアプローチで準備期間を数週から数時間に短縮します。

## MCP の理解：すべてを動かすプロトコル

これがすべて実現できるのは、**Model Context Protocol (MCP)** のおかげです——AI エージェントがツール、サーバー、互いとどのように通信するかを定義するオープンスタンダード。

**シンプルに言うと：** MCP は AI エージェントの USB-C です。USB-C がデバイスを周辺機器に接続する方式来規準化するように、MCP は AI モデルをツール、データソース、他のエージェントに接続する方式来規準化します。

Cowork は **Streamable HTTP** 経由で MCP を実装しています——継続的な WebSocket 接続を必要としない軽量トランスポートで、あらゆる HTTP クライアントと連携できます。これにより、CI/CD パイプライン、サーバーレス関数、エッジコンピューティング環境への統合が容易になります。

カスタム統合を作成したい開発者向けには、[Cowork リポジトリ](https://github.com/slashman413/cowork)に完全な MCP ツールリストが文書化されています——`create_task`、`register_agent`、`get_roster`、`claim_task`、`complete_task`、`file_report`、`heartbeat` などを含む。

## 正しいエージェントアーキテクチャの選択

すべてのプロジェクトに 285 人のエージェントが必要です。以下の意思決定フレームワークを参照してください：

### 単一プロジェクトチーム（1〜3 エージェント）
- **適している**：小規模リポジトリ、個人プロジェクト、個人クリエイター
- **設定**：一つの LLM バックエンドに接続し、3〜5 人のエージェントロールを使用
- **例**：コードレビュアー + ライター + リサーチャー

### 部門レベルチーム（5〜20 エージェント）
- **適している**：小チーム、スタートアップ、代理店
- **設定**：複数の LLM バックエンド、部門専属エージェント
- **例**：完全なエンジニアリング部門 + マーケティングチーム + データアナリスト

### エンタープライズレベルチーム（50+ エージェント）
- **適している**：プロダクト会社、大規模コンテンツ運営
- **設定**：リモート脳の登録、カスタムエージェント作成、API 自動化
- **例**：全 19 部門、マルチプラットフォーム LLM ルーティング、CI/CD 統合

Cowork はすべての三つのレベルにスケーラブル——小規模から始め、ニーズの成長に伴ってエージェントを増やせます。

## よくある落とし穴

本番環境でマルチエージェントシステムを数か月運用した結果、最もよくある間違いは以下の通りです：

### 1. エージェントが多すぎる、コンテキストが少なすぎる
簡単なタスクに 20 人のエージェントを使うのはやめましょう。各エージェントはレイテンシとコンテキストオーバーヘッドを増加させます。2〜3 人のエージェントから始め、必要と確認してから増やしてください。

### 2. エージェントロールの品質を無視する
不適切に書かれたエージェント定義は不適切な結果を生みます。正確なロール説明、スキルリスト、プロンプトインストラクションを注意深く設計する時間を投資してください。Cowork の既存の 285 人のエージェントはすべて注意深く設計されています——それをテンプレートとして使ってください。

### 3. タスク完了追跡を見逃す
必ず完了追跡を設定してください。Cowork のダッシュボードは一目で分かりますが、長時間実行されるワークフローの場合は通知も設定すべきです。

### 4. 単一ベンダー依存
少なくとも二つの LLM バックエンドに接続してください。一つのプラットフォームがダウンするかレート制限を受けた場合、エージェントチームがもう一方に切り替えます。Cowork は自動的にマルチプラットフォームルーティングを処理します。

### 5. 重要な意思決定に人間の検証がない
セキュリティ監査、財務分析、法務レビュー——AI 出力に基づいて行動する前に、必ず人間の検証を行ってください。エージェントは強力なアシスタントですが、高リスクな作業領域における自律的判断者ではありません。

## よくある質問

**Q：Cowork を使うために Python や AI エンジニアリングの知識が必要ですか？**
A：いいえ。`git clone` と `npm install` が実行できれば、Cowork を設定できます。エージェントの roster は事前設定済みです。

**Q：Cowork をクラウドサーバー上で実行できますか？**
A：はい。Cowork は Node.js がインストールされたあらゆるマシンで実行できます。VPS、クラウド VM、ラズベリーパイへのデプロイが可能です。ダッシュボードと MCP エンドポイントはネットワーク経由でアクセスできます。

**Q：同時にいくつのエージェントを実行できますか？**
A：Cowork は同時実行数に制限を設けていません——制限はあなたの LLM バックエンドとハードウェアによります。現代の GPU を備えた単一マシンで 5〜10 人のエージェントを並行実行できます。複数のバックエンドを備えたエンタープライズ設定ではより高い数にスケーリング可能です。

**Q：Cowork は無料でオープンソースですか？**
A：はい。Cowork は MIT ライセンスで、[GitHub](https://github.com/slashman413/cowork) で入手可能です。有料プランはありません、隠し制限もありません。

**Q：Cowork は CrewAI / AutoGen と何が異なりますか？**
A：Cowork は「幅」に焦点を当てています——19 部門にわたる 285 以上の事前設定エージェント、マルチプラットフォーム LLM サポート、ファイルシステムファーストのアプローチ。CrewAI は順序エージェントチェーンに優れ、AutoGen は会話型マルチエージェントパターンに優れています。Cowork の優位性は、厳選された専門家の roster にリアルタイムでアクセスできることです。
