## 你想建一個網站？先搞清楚：你需要的是「網站」還是「產品」

在開始比較之前，先問你一個問題：你想建的網站是什麼？

是**作品集網站**？需要美觀、快速、少維護。
是**部落格**？需要 SEO 強大、內容管理方便。
是**銷售頁面**？需要轉換率高、整合支付。
是**部落格 + 產品銷售**？需要結合內容和電商。
是**SaaS 產品頁**？需要整合登入、訂閱管理。

不同的需求，答案完全不同。

根據 2026 年的數據，全球無代碼（No-Code）網站建置市場已達到 150 億美元規模，年成長率 24%。其中，Webflow 佔了 35% 的市場份額，Wix 佔 25%，WordPress.com 佔 15%，而新興的 Framer 正以每年 200% 的速度成長。

但這裡有個被忽略的選項：**靜態網站生成器**（如 Hugo、Astro、Next.js）。這些工具雖然被歸類為「有代碼」，但其實用性在 2026 年已經非常接近 No-Code 的體驗，而且在性能、SEO 和成本上有顯著優勢。

這篇文章會比較目前市面上最主要的四個建站方案：

1. **Webflow** — 視覺化設計的標竿
2. **Framer** — AI 驅動的新一代設計工具
3. **Hugo** — 最快靜態網站生成器
4. **WordPress** — 最成熟的 CMS

我們會從設計靈活性、SEO 能力、學習曲線、成本、部署方便性等七個維度進行比較。

最後，我會分享我在 [Slashman Tools](/multi-agent-coworking-platform/) 專案中選擇建站方案的思考和決策過程。

## Webflow：視覺化設計的標竿

Webflow 是 No-Code 領域最著名的平台之一，它以「視覺化設計 + 產生乾淨程式碼」的理念吸引了數十萬設計師和開發者。

### Webflow 的核心優勢

**視覺化編輯器**：Webflow 的編輯器讓你可以像在使用 Figma 或 Photoshop 一樣設計網站，但每次操作都會自動產生乾淨的 HTML、CSS 和 JavaScript 程式碼。這意味著你不需要寫程式，但最終產出的是標準的網頁代碼。

**高度客製化**：Webflow 允許你完全控制每個 CSS 屬性、HTML 結構、動畫效果。沒有模板限制，你想怎麼設計就怎麼設計。

**内建 CMS**：Webflow 提供內建的內容管理系統，你可以建立自定義內容模型（如文章、產品、團隊成員），然後在前端模板中呼叫這些資料。

**動畫和互動**：Webflow 的「Animations & Interactions」功能允許你建立複雜的滾動動畫、懸停效果、頁面轉場，而不需要寫一行 JavaScript。

**SEO 工具**：Webflow 內建了完善的 SEO 工具：自訂 Meta 標籤、Canonical 標籤、Sitemap 生成、301 重定向、結構化數據等。

### Webflow 的缺點

**價格偏高**：Webflow 的 Starter 方案每月 $14，包含 2 個頁面。Basic 方案 $29/月，包含 5 個頁面。CMS 方案 $49/月，包含 1000 筆內容項目。Ecommerce 方案 $212/月。對於個人部落客來說，這個價格可能偏高。

**學習曲線**：雖然 Webflow 宣稱是 No-Code，但如果你想發揮它的全部潛力，需要了解 CSS（Flexbox、Grid、Positioning）等基礎概念。完全不懂 CSS 的人可能會遇到瓶頸。

**平台鎖定**：你的網站是建立在 Webflow 平台上的。如果你決定離開，需要手動遷移整個網站。

### Webflow 適合誰？

- 設計師想要建立自己的作品集網站
- 創業團隊想要快速建立美觀的產品頁
- 行銷人員想要建立轉換率高的 Landing Page

> 如果你是在經營數位產品，[Gumroad 數位產品策略](/gumroad-digital-product-strategy/) 中提到的銷售頁面設計，Webflow 是一個非常好的選擇。

### Webflow 評分：設計靈活性 9/10 | SEO 能力 8/10 | 學習曲線 6/10 | 速度 8/10 | 成本效益 6/10

## Framer：AI 驅動的新一代設計工具

Framer 在 2024 年推出建站功能後，迅速成為 No-Code 領域的熱門選擇。它的最大賣點是：**用 AI 生成網站，然後視覺化編輯**。

### Framer 的核心優勢

**AI 生成網站**：Framer 的 AI 功能是目前所有工具中最強大的。你只需要輸入一段文字描述（例如「一個科技風格的 AI 工具介紹頁面」），AI 會在幾分鐘內生成一個完整的網站。你不需要從零開始設計。

**即時協作**：Framer 的協作功能和 Figma 一樣流暢。多人可以同时編輯同一個頁面，即時看到彼此的修改。

**React 基礎**：Framer 建立在 React 之上。如果你懂 React，可以在 Framer 中插入自定義 React 元件，獲得無限的客製化能力。

**速度極快**：Framer 網站的加載速度非常快，特別是在行動裝置上。這得益於它的 CDN 架構和 React 的效能優化。

**內建分析**：Framer 內建了網站分析功能，包含頁面檢視、點擊熱圖、訪客來源等。不需要額外安裝 Google Analytics。

### Framer 的缺點

**CMS 功能相對較弱**：Framer 的 CMS 目前還不如 Webflow 成熟。雖然支援基礎的內容管理，但複雜的內容模型和多關聯仍受限。

**價格持續上漲**：Framer 的定價近年來多次上調。目前 Basic 方案 $5/月（包含 1 個頁面），Plus 方案 $15/月（無限頁面），Pro 方案 $25/月（包含 CMS 和客戶項目）。

**生態系統較新**：相對於 Webflow 和 WordPress，Framer 的外掛和整合生態系統還在成長階段。

### Framer 適合誰？

- 個人創作者想要快速建一個美觀的部落格或作品集
- 團隊想要用 AI 快速生成 Landing Page
- 設計師想要一個更接近 Figma 的建站工具

> Framer 的 AI 生成功能特别适合那些「有想法但不知道從何開始」的創作者。如果你正在規劃數位產品上市，[數位產品上市策略](/digital-product-launch-strategy-1000-users/) 文章涵蓋了從網站設計到轉換的完整方法論。

### Framer 評分：設計靈活性 9/10 | SEO 能力 8/10 | 學習曲線 8/10 | 速度 9/10 | 成本效益 7/10

## Hugo：最快靜態網站生成器

Hugo 是 Go 程式語言開發的靜態網站生成器。它被稱為「世界上最快的網站生成器」——因為它能在一毫秒內生成包含數千頁的網站。

### Hugo 的核心優勢

**極致速度**：Hugo 的構建速度是所有網站生成器中最快的。即使是包含 10,000 頁的大型網站，也只需不到 1 秒。這意味著開發體驗極其流暢。

**完全免費**：Hugo 本身完全免費開源。唯一的成本是你的域名和託管費用（如果使用 Netlify 或 Vercel，託管成本可以低至每月 $0）。

**最佳 SEO**：靜態網站天然具有優異的 SEO 潛力。Hugo 生成的 HTML 文件乾淨、結構化、可爬取，而且速度極快。

**Git 工作流**：Hugo 的內容是用 Markdown 寫成的，存放在 Git 倉庫中。這意味著你可以用版本控制管理你的內容，與團隊協作，甚至用 CI/CD 自動化部署。

**多語言支援**：Hugo 內建了強大的多語言支援，可以輕鬆建立中文、英文、日文等多語言網站。

**生態成熟**：Hugo 擁有超過 100 個官方主題和數百個社群主題。對於這個專案，我們使用了 Hugo Stack 主題（由 Cal-H 開發），它提供了現代化、響應式、SEO 友好的開箱即用體驗。

### Hugo 的缺點

**需要 Git 和命令行知識**：雖然 Hugo 的內容是用 Markdown 寫的，但初始設定、部署、更新都需要使用命令行工具和 Git。這對完全不懂技術的使用者來說是一個門檻。

**沒有視覺化編輯器**：你不能像 Webflow 或 Framer 那樣直接在瀏覽器中編輯網站內容。你需要編輯 Markdown 文件，然後重新構建。

**主題客製化需要 HTML/CSS 知識**：如果你想要修改主題的外觀，需要了解 Hugo 的模板語言（Go Templates）和 CSS。

**沒有內建 CMS**：Hugo 本身不具備 CMS 功能。你需要搭配外部的 CMS（如 Decap CMS、Forestry）或使用 Git 來管理內容。

### Hugo 適合誰？

- 開發者想要建立快速、SEO 優化的部落格
- 技術部落格作者和工程師社群
- 預算有限但需要專業級網站的創作者
- 需要多語言支援的網站

> 事實上，你現在正在閱讀的這個網站就是使用 Hugo 建置的。我們選擇 Hugo 是因為它的速度、SEO 能力和完全免費的託管方案。對於一個技術博客來說，Hugo 可能是最理想的選擇。

### Hugo 評分：設計靈活性 7/10 | SEO 能力 10/10 | 學習曲線 4/10 | 速度 10/10 | 成本效益 9/10

## WordPress：最成熟的 CMS

WordPress 是全球最流行的網站建置平台，佔據了全球 43% 的網站市場份額。雖然它不是 No-Code 工具（它需要安裝和配置），但它的易學性讓它成為 No-Code 競爭者之一。

### WordPress 的核心優勢

**最大的生態系統**：WordPress 擁有超過 60,000 個外掛和 10,000 個主題。無論你需要什麼功能，幾乎都有現成的外掛可以安裝。

**完全可控**：你可以完全控制你的網站代碼、資料庫、伺服器。沒有平台鎖定的風險。

**電商能力**：透過 WooCommerce，WordPress 可以變成一個功能完整的電商平台。

**SEO 外掛**：Yoast SEO 和 RankMath 等外掛讓 WordPress 的 SEO 設定非常簡單。

**社群支援最大**：無論你遇到什麼問題，幾乎都可以在社群中找到解決方案。

### WordPress 的缺點

**安全性問題**：WordPress 是最常被駭的 CMS 之一。你需要定期更新外掛、主題和核心程式碼，並安裝安全外護。

**速度問題**：WordPress 需要資料庫（MySQL），而且很多使用者安裝了太多外掛，導致網站變慢。

**需要維護**：WordPress 網站需要定期更新外掛、備份、清理垃圾評論。這需要時間和技術知識。

**使用者體驗不一致**：由於外掛和主題的多樣性，WordPress 網站的使用者體驗可能很不一致。

### WordPress 適合誰？

- 需要完整電商功能的網站
- 有技術團隊可以維護 WordPress 的企業
- 需要高度客製化功能的網站

> 對於個人創作者和小團隊來說，WordPress 可能是「過度設計」（Overkill）。如果你只需要部落格或簡單的銷售頁面，Webflow 或 Hugo 可能更適合。

### WordPress 評分：設計靈活性 8/10 | SEO 能力 8/10 | 學習曲線 5/10 | 速度 6/10 | 成本效益 6/10

## 深度比較：七個關鍵維度詳細分析

### 1. 設計靈活性

**Webflow**：⭐⭐⭐⭐⭐
- 最接近「設計工具」的建站平台
- 完全控制 CSS、HTML、動畫
- 從零設計或基於模板

**Framer**：⭐⭐⭐⭐⭐
- AI 生成作為起點，然後自由編輯
- React 基礎，可插入自定義元件
- 直覺的拖曳編輯

**Hugo**：⭐⭐⭐⭐
- 主題提供基礎設計
- 需要修改 HTML/CSS 才能深度客製化
- 自由度高但需要技術能力

**WordPress**：⭐⭐⭐
- 主題提供設計框架
- 頁面編輯器（如 Elementor）提供視覺化編輯
- 但容易產生不必要的複雜 CSS

> **結論**：如果你追求極致的設計自由度和美觀度，Webflow 和 Framer 是最好的選擇。

### 2. SEO 能力

**Hugo**：⭐⭐⭐⭐⭐
- 純靜態 HTML，Google 最喜歡的格式
- 極快的加載速度
- 完全可控的 Meta 標籤、Sitemap、結構化數據

**Webflow**：⭐⭐⭐⭐
- 良好的 SEO 功能
- CDN 託管，速度快
- 但產生了一些不必要的 JavaScript

**Framer**：⭐⭐⭐⭐
- 良好的 SEO 基礎
- 速度快
- 但動態渲染可能影響爬取

**WordPress**：⭐⭐⭐⭐
- 透過外掛可以達到很好的 SEO
- 但配置錯誤可能影響 SEO
- 速度依賴於優化和外掛選擇

> **結論**：如果 SEO 是你的首要考量，Hugo 是最佳選擇。Webflow 次之。

### 3. 學習曲線

**Framer**：最容易上手，特別是它的 AI 生成功能。即使完全不懂設計，也能在 30 分鐘內建出一個像樣的網站。

**Webflow**：中等。你需要了解基本的 CSS 概念，但視覺化編輯器讓上手變得容易。

**WordPress**：基本使用很容易（安裝外掛、選擇主題），但進階定制需要技術知識。

**Hugo**：最難。你需要懂 Git、命令行、Markdown。但一旦學會，效率極高。

> **結論**：如果你是完全新手，從 Framer 開始。如果你懂一點技術，Hugo 值得學。

### 4. 網站速度

**Hugo**：最快（靜態 HTML，零資料庫查詢）
**Framer**：很快（React + CDN）
**Webflow**：快（CDN 託管，但產生一些 JavaScript）
**WordPress**：依賴優化（資料庫 + 外掛可能拖慢速度）

> **結論**：速度是 Hugo 的絕對優勢。對於內容密集的部落格，Hugo 的速度優勢特別明顯。

### 5. 成本效益

**Hugo**：最便宜。Hugo 本身免費，託管可以免費（GitHub Pages、Netlify、Cloudflare Pages）。唯一的成本是域名費用（約 $10-15/年）。

**Framer**：便宜。Basic 方案 $5/月，包含基本建站功能。Pro 方案 $25/月，包含 CMS 和更多進階功能。

**Webflow**：中等。Starter $14/月，CMS $49/月。價格隨著功能增加快速上升。

**WordPress**：視需求而定。基本託管約 $3-10/月，但加上外掛、主題、開發時間，成本可能快速增加。

> **結論**：如果預算有限，Hugo 是唯一一個「完全免費」的選項。

### 6. 部署和維護

**Framer**：最容易。點擊「發佈」，網站就部署好了。不需要任何技術知識。

**Webflow**：容易。點擊「發佈」，自動部署到 Webflow 伺服器。

**WordPress**：中等。需要設定託管環境、安裝外掛、處理更新。

**Hugo**：需要技術知識。需要配置 Git、CI/CD（如 GitHub Actions 自動部署到 Netlify/Vercel）。

> **結論**：Framer 和 Webflow 提供最好的部署體驗。Hugo 需要一些設定，但一旦配置完成，維護幾乎為零。

### 7. 多語言支援

**Hugo**：最強大。內建多語言架構，可以輕鬆建立中文、英文、日文等多語言網站。

**Webflow**：內建多語言功能（Pro 方案以上）。

**Framer**：需要外掛或手動配置。

**WordPress**：需要外掛（如 WPML、Polylang）。

> **結論**：如果你需要多語言網站，Hugo 和 Webflow 是最好的選擇。

## Slashman Tools 的選擇：為什么我用 Hugo 建博客

作為 Slashman Tools 的開發者，我選擇使用 Hugo 來建置我們的部落格。這個決定不是輕易做出的——我評估了所有四個選項，並考慮了以下因素：

**1. 內容是核心，速度是關鍵**

我們的部落格專注於技術內容，讀者期望快速的加載體驗。Hugo 的靜態生成確保了我們的頁面加載時間在 1 秒以內，這對於 SEO 和使用者體驗至關重要。

**2. 完全免費的託管**

作為一個個人專案，我選擇使用 GitHub Pages 託管 Hugo 網站，完全零成本。如果用 Webflow 或 Framer，每月需要支付 $14-25 的費用。

**3. Git 工作流**

我用 Git 管理所有部落格內容。這意味著：
- 我可以回滾到任何版本
- 可以多人協作
- 可以自動化 CI/CD（GitHub Actions 自動部署）

**4. 長期穩定性**

Webflow 和 Framer 是商業平台，價格可能會調整，功能可能會改變。Hugo 是開源的，你的內容永遠是你的。

**5. 多語言架構**

我們的部落格支援中文（繁體、簡體）和英文。Hugo 的多語言支援讓這個架構非常乾淨。

## 實戰教學：如何用 Hugo 建立你的第一個部落格

既然選擇了 Hugo，讓我給你一個快速上手指南。

### 第一步：安裝 Hugo

```bash
# macOS
brew install hugo

# Ubuntu/Debian
sudo apt install hugo

# 或使用 Snap
sudo snap install hugo
```

### 第二步：建立網站

```bash
# 建立新的 Hugo 網站
hugo new site my-blog

# 進入目錄
cd my-blog

# 安裝 Hugo Stack 主題
git init
git submodule add https://github.com/CaiJimmy/hugo-theme-stack.git themes/hugo-theme-stack
```

### 第三步：建立第一篇文章

```bash
# 建立一篇文章
hugo new post/hello-world.md

# 編輯文章（用你喜歡的編輯器）
vim content/post/hello-world.md
```

### 第四步：本地預覽

```bash
# 啟動本地開發伺服器
hugo server
```

打開瀏覽器訪問 `http://localhost:1313`，你就能看到你建立的網站了。

### 第五步：部署到 GitHub Pages

1. 在 GitHub 建立一個新 Repository
2. 將 Hugo 網站目錄推送到該 Repository
3. 在 Repository Settings → Pages 中選擇部署分支
4. 等待 GitHub Actions 自動部署完成

完成！你的 Hugo 部落格就上线了。

## 常見問題（FAQ）

### Q1：我是完全新手，該選哪一個？

A：如果你的目標是「快速建一個像樣的網站」，選 **Framer**。它的 AI 生成功能讓你不需要任何技術或設計背景。如果你懂一點技術，想長期經營一個內容豐富的部落格，選 **Hugo**。

### Q2：Hugo 真的適合非技術人員嗎？

A：坦白說，Hugo 對完全不懂技術的人來說，初期門檻比較高。但一旦你學會了基本的命令行操作和 Markdown 寫作，使用體驗非常好。如果你覺得門檻太高，可以用 **Decap CMS**（原 Netlify CMS）作為 Hugo 的視覺化 CMS。

### Q3：什麼情況下應該選 WordPress？

A：當你需要完整的電商功能、需要大量外掛擴展、或者有技術團隊可以維護時，WordPress 是最佳選擇。對於個人創作者和小型團隊，Webflow 或 Hugo 通常是更好的選擇。

### Q4：Webflow 和 Framer 有什麼區別？

A：Webflow 更像是一個「網頁設計工具」，適合從零開始設計複雜的網站。Framer 更像是一個「AI 輔助的設計工具」，適合快速生成和編輯。如果你重視設計自由度，選 Webflow。如果你重視速度和 AI 生成，選 Framer。

### Q5：靜態網站生成器和 No-Code 平台誰更好？

A：取決於你的需求：
- **需要視覺化編輯** → No-Code（Webflow、Framer）
- **需要 SEO 極致優化** → 靜態生成器（Hugo）
- **需要快速起步** → No-Code（Framer 的 AI 生成）
- **需要長期成本和穩定性** → 靜態生成器（Hugo）

## 結論：根據你的需求選擇

如果你要我給一個簡單的決策框架：

| 你的情況 | 推薦工具 |
|---------|---------|
| 完全新手，想要快速建網站 | **Framer** |
| 設計師，想要最大設計自由 | **Webflow** |
| 開發者，想要速度和 SEO | **Hugo** |
| 企業用戶，需要完整 CMS | **WordPress** |
| 預算有限但需要專業網站 | **Hugo（免費託管）** |
| 需要多語言網站 | **Hugo** 或 **Webflow** |
| 想要 AI 生成網站 | **Framer** |

在 2026 年，沒有「最好」的網站建置工具，只有「最適合」你的工具。選擇之前，先想清楚你的需求優先順序是什麼：是速度、SEO、設計自由度、還是簡單易用？

對於 Slashman Tools 這樣以內容為核心的專案，我選擇了 Hugo。對於需要快速建銷售頁面的創作者，我會建議 Framer 或 Webflow。對於需要完整電商功能的，WordPress 或 Shopify 是更好的選擇。

你的選擇取決於你的優先級。想清楚了，就開始吧。
