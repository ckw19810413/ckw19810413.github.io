在南方有一座以文字立國的小國，國名為**「句」**。

句國的子民不說廢話。王室的法典、邊境的檄文、廟裡的經卷，都要由**御筆樓**裡的一群書吏來寫。而御筆樓的最高處，住著一位**墨卿**——全句國最老、也是最慢的書法大師。

墨卿的慢，是有緣故的。他每寫一個字，都要先凝神、研墨、調筆，再落下去；一個字寫完，才去想下一個字。所以他一息只寫一字，一息就是一整盞油燃盡、再換一盞的時間。可他的字，字字端正、章法無一可挑剔，全句國無人能出其右。

---

### 第一幕：寫不完的詔書

那一年，北方邊境吃緊，王下了一道長得沒完沒了的詔書，要御筆樓三日內寫成。墨卿接了旨，坐在樓上，一個字一個字地磨。

一天過去，才寫了三十幾個字。

他不算慢——就他「一息一字」的節奏而言，他是全句國最快、也最精確的那一個。可問題不在他個人，而在**結構**：他必須**寫完一個字，才能決定下一個字**。第二個字取決於第一字，第三個取決於前兩個，一路連鎖下去。他寫得再快，也快不過「一息一字」的下限——因為**每個字都要重新研墨、重新調筆、重新把整張紙再看一遍，才能決定下一筆往哪裡走**。

這座御筆樓，卡住他的不是筆，是那套「一個字一個字來」的寫法。

---

### 第二幕：快筆書童

樓下有一個書童，名叫**阿速**。阿速字寫得不精，甚至有些潦草，但他手腳極快：墨卿寫一字的一息，他能趕出一整行。

有一天，墨卿對他說：

> 「別干寫。你照著我的章法，先把整頁都『趕』出來——快就好，寫錯字不罪，但你要照我的筆意來，別自己亂加。我來校。」

阿速愣了：「那您還得一個字一個字校，還不如您自己寫。」

墨卿搖頭：

> 「不是。你**一次**把一整行趕出來，我**一眼**看整行。我一眼看下去，能同時核對整行有沒有離譜——我核一整行花去的工夫，跟我自己寫一個字的工夫，**差不多**。可你一行就出了八九個字。」

阿速眼睛亮了，照做。他唰唰趕出一行九個字，把紙往墨卿面前一推。

### 第三幕：朱筆校訂，只改第一個錯字

墨卿拿起朱筆，從頭核起：

- 第一字，合我的筆意，蓋朱印，留；
- 第二字，合，蓋印，留；
- 第三字，合，蓋印，留；
- ……
- 第七個字，不對。阿速寫得太潦草，這筆我絕不會這樣落。

墨卿**沒有把整行全擦了重寫**。他只做三件事：

1. 前六個「蓋過印」的字留下——既然我核過、認了，就等同我親手所書；
2. 第七字，我**自己**重寫一個我該寫的字；
3. 紙還給阿速，從第七字之後，讓他再繼續趕。

如此反覆：趕一批、校一批、留前綴、補一個，再趕下一批。

---

### 第四幕：關鍵的一條規矩

阿速問：「我趕出來的字，您就全收，還是挑您喜歡的就留？」

墨卿答：「不全收，也不憑喜好。我用一條鐵律：**你趕出來的字，我按『我本來有多大把握會寫這個字』來決定收不收。** 你寫的字，恰好也是我大概率會寫的那個，我就收；你寫的字，我其實更想寫另一個，我就退回，改寫成我真正會落的那個。」

「可是，」阿速追問，「那最後這紙字，跟我自己一個字一個字慢慢寫出來的，一樣嗎？」

墨卿笑了：

> 「**一樣。統計上，分不出差別。** 我收的、我改的、我補的，合起來，跟我一個人從頭寫到尾，分佈上**分毫不差**。我不是在『快』，我是在『不降質』的前提下，少做幾趟最慢的活。」

### 第五幕：書童不能太差

可墨卿話鋒一轉：

> 「還有一件事。你趕得再快，若你寫的字**大半都離我的筆意太遠**，那我每次一眼核過去，多半第一個字就要打回去——那我就白核了一趟，只白搭一個字，還倒貼了你趕字的工夫。所以你得**跟我筆意夠像**，你趕得多、我才能連著收得多。」

他頓了頓：「你太慢，我白等；你太差，我白核。所以要挑一個**筆意像我、但比我快得多**的人來趕。挑對了，我三日能寫完這卷詔書；挑錯了，反而拖慢。」

那一卷詔書，最終趕完得比原本快了近兩倍，而**紙面上每一個字，都跟墨卿親筆所書無法分辨**。

---

## 揭曉：這則寓言讲的是「投機解碼」（Speculative Decoding）

故事裡的每一位角色、每一條規矩，都對應到大語言模型**推論（inference）**裡的一個研究生級概念——**投機解碼（Speculative Decoding，又稱投機取樣 / Draft-and-Verify）**，由 Leviathan 等人（DeepMind，ICLR 2023）正式提出，是現在讓 LLM「變快卻不降質」的核心技巧之一。對照本週新聞：Tenstorrent 做開放權重晶片、CoreWeave 收購 Weights & Biases、OpenAI 衝 1.25 兆估值——這些資本與硬體的投資，底層都在回答同一件事：**自回歸推論太慢、太貴，怎麼把「生成 token 的速度」提上去，同時不犧牲品質？投機解碼就是演算法層最乾淨的答案之一。**

### 概念本質：LLM 為什麼慢，以及「投機」如何加速

現代 LLM 用**自回歸（autoregressive）**方式生成：要產出第 $t{+}1$ 個 token，必須先把前 $t$ 個 token 餵進去、跑**一整個模型的前向計算**。這帶來兩件事：

- **串行的下界**：第 $t{+}1$ 個 token 依賴第 $t$ 個，無法天然並行；生成 $N$ 個 token 就要做 $N$ 次前向。
- **頻寬受限（memory-bandwidth-bound）**：每次前向都要把數十到數百億參數從記憶體搬過一次，而真正算的量很小——所以「算」不是瓶頸，**把模型權重搬進搬出**才是。多算幾個 token 的邊際算力成本很低，但每多「等一個字」就多一次權重搬運。

投機解碼正是利用這個不對稱：

1. **draft（草稿）**：用一個**小得多、快得多**的模型（或量化／剪枝版）快速連推 $k$ 個候選 token。小模型便宜，趕 $k$ 個 token 幾乎不心疼。
2. **verify（校訂）**：把這串 $k$ 個候選**整串**餵給大模型（target），**一次前向**同時算出每個位置在大模型下的條件機率。關鍵洞察：核對整串的成本，跟大模型自己算一個 token 的邊際成本**幾乎相同**——一次前向，順手把整段都驗證了。
3. **accept / reject（收／退）**：從前到後走，逐個用**拒絕取樣（rejection sampling）**判斷——以 $\min\!\big(1,\; p_{\text{target}}(x)/p_{\text{draft}}(x)\big)$ 的機率接受草稿字。
4. **補正（resample）**：在第一個被拒的位置，用修正分佈 $\big[\max(0,\; p_{\text{target}}-p_{\text{draft}})\big]$（正規化後）**由大模型重抽一個字**，再讓草稿模型從此處繼續趕下一批。

**核心保證（研究生級要點）**：這套「接受＋修正」機制，使最終輸出序列的分佈，**在數學上完全等於**「只用大模型、不投機」的分佈——**不犧牲任何樣本品質**，卻把「一次大模型前向」換成「一次前向出 $k{+}1$ 個 token」。實測加速常達 **2～3×**（視草稿命中率而定），且加速來自**少搬幾次權重**，而非偷換答案。

> 這就是寓言裡墨卿那句「**分佈上分毫不差**」的嚴格版：投機解碼不改變模型會寫出什麼，它只改**寫多快**。

### 為什麼「書童不能太差」

加速比取決於**草稿命中率**（acceptance rate）。草稿模型與目標模型筆意越像、接受的候選串越長，加速越接近理論上界 $k{+}1$。草稿模型若太弱（命中率低），大模型每次前向幾乎都浪費在「白核一個就要打回」上，加速趨近 1，甚至不如直接自己寫——正對應寓言裡「你太差，我白核，反而拖慢」。所以實務上：草稿要**小而像**（常是目標模型的量化／剪枝版，或共用的更早層），且 $k$ 要調在「多趕幾個字」與「命中率下滑」之間。

### 故事隱喻對照表

| 寓言中的元素 | 投機解碼中的概念 | 一句話解析 |
|---|---|---|
| **墨卿**（全句國最慢、最精確的大師） | **目標模型**（large target LLM） | 慢，但分佈正確，是「地面真相」。 |
| **阿速**（手快、潦草、趕一整行） | **草稿模型**（small draft / fast LM） | 便宜、快、會出錯，負責「趕出候選」。 |
| **一息一字、寫完一個才想下一個** | **自回歸生成**（串行的下界） | 每個 token 都要整模型前向，無法天然並行。 |
| **每寫一字都要重新研墨調筆** | **memory-bandwidth-bound 推論** | 每次前向都要搬動全部權重；邊際算力便宜，搬運貴。 |
| **阿速一次趕一整行** | **draft 階段：小模型連推 $k$ 個候選** | 用小模型便宜地「投機」出一段候選。 |
| **墨卿一眼核整行** | **verify 階段：大模型一次前向驗整串** | 一次前向即可給整串打分——投機的關鍵不對稱。 |
| **收前綴、只改第一個錯字** | **接受最長匹配前綴＋從首個被拒處重抽** | 保留已驗證前綴，只補錯的那個，再繼續投機。 |
| **收字看「我本來多大把握會寫這字」** | **拒絕取樣接受準則** $\min(1, p_t/p_d)$ | 草稿字越像大模型本會寫的，越容易收。 |
| **被拒處由墨卿親手補一個** | **從 $\max(0, p_t-p_d)$（正規化）重抽** | 修正分佈，保證不偏離目標分佈。 |
| **「統計上分不出差別」** | **輸出分佈與只用目標模型完全一致** | 不降品質：加速不靠偷換答案。 |
| **三日寫完，快了約兩倍** | **2～3× wall-clock 加速** | 一次前向換 $k{+}1$ 個 token。 |
| **「挑一個筆意像我、但比我快得多的」** | **草稿模型須與目標同風格且夠快** | 命中率決定實際加速，差稿子會拖垮整體。 |
| **整卷詔書** | **一條長生成序列**（長上下文／長回答） | 序列越長，串行的痛感越大，投機解碼收益越明顯。 |

### 為什麼是「研究生水平」

投機解碼表面像「找個快的幫忙寫、自己來核」，但要把「**加速**」與「**不降品質**」同時拿到，必須理解三層：

- **自回歸的結構性瓶頸**：token 依前文、天然串行；而 LLM 推論是 memory-bandwidth-bound 而非 FLOP-bound——這是「為什麼要投機」的物理直覺。
- **前綴可共享**：驗證一整串與驗證其前綴，成本幾乎只差在邊際，這是「一次前向驗多字」之所以成立的關鍵；並非所有模型／架構都同等受益。
- **分佈無偏性**：接受／重抽機制保證**邊際與條件分佈都與目標一致**（可證）——這把它與「截斷 top-1」「換小模型硬扛」等**近似**方法區分開：後者會悄悄改答案分佈，投機解碼不會。

## 研究生延伸閱讀

- Leviathan et al., *Fast Inference from Transformers with Speculative Decoding*, ICLR 2023（arXiv:2211.17192）——投機解碼的奠基工作，含接受／重抽的分佈無偏證明。
- Chen et al., *Accelerating Transformer Inference with Retrieval-Based Generation*, 2023（Ret-LLM）——以檢索代替自回歸草稿的獨立並行線。
- *Universal Speculative Decoding* 與 *Medusa: Simple, Fast Inference from Multi-head Speculation*——把投機解碼通用化、多頭並行投機。
- Agarwal et al., *Taming LLMs: Practical Approaches to Mitigate Inference Cost*——把投機解碼放進「推論成本」系統性框架裡的一節。
- 想補「為什麼 LLM 推論是頻寬受限而非算力受限」：閱讀 Hestness et al. 的 roofline 分析，理解 memory-bandwidth-bound 如何決定 $k$ 的合理範圍。
